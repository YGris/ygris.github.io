# 嵌入式

该文档提供嵌入式开发的基本概念和相关板块导航

- [STM32](./Stm32.md)

## 概念

1. 开发板: 通常由 **MCU** (Microcontroller Unit，微控制器，俗称芯片) 和外围电路构成。能够正常调试使用的开发板也称为 **最小系统板** ，最小系统板通常要求外围电路包括如下内容：
    1. 电源电路: 将外部电源降压/稳压到3.3v(或其他合适电压)供**MCU**使用
    2. 复位电路：确保MCU正常重启
    3. 时钟电路：外部晶振，提供精确的时间基准([为什么需要时钟基准？](#为什么单片机的运行需要时钟基准))
    4. 启动配置电路：BOOT0/BOOT1引脚配置，决定从哪里启动
    5. 下载/调试接口：如SWD()接口,用于烧录程序和调试
    6. 板载外设：用户交互元件（按键、LED、蜂鸣器等）、板载传感器（温湿度传感器，OLED屏幕等）、扩展排针等。嵌入式的学习除了学习MCU内部如何处理和控制数据，处理的数据原料和结果也很大程度上来自板载外设或用板载外设进行展示
2. MCU: 微控制器中也有由若干电路和元件组成的 **外设**
   | 芯片板块 | 主要功能 |
   | -------- | --------------------------------------------- |
   | CPU | 执行指令、运算、调度其他板块 |
   | 存储单元 | SRAM或Flash，存储代码或者数据 |
   | 外设 | GPIO、定时器、串口、I2C、SPI、ADC、DAC、CAN等 |
   | 电源 | 分配电压、电源管理与低功耗控制 |
   | 时钟树 | 提供时间基准 |
   | 总线 | 连接各模块的通道 |

3. GPIO: 通用输入输出，通过软件控制对应引脚的输入输出信号，以控制外围设备
4. 中断处理：紧急响应机制，当有突发事件时，CPU会立刻暂停并保存当前任务，优先处理中断任务。
    1. 中断优先级：由CPU根据中断源裁决，优先响应更紧急的中断源
    2. 典型的中断事件：
        - 外部中断：按键按下触发的电平变化
        - 定时器中断
        - 通信中断
        - 模拟信号转换中断：比如看门狗或低电压检测等系统级中断
5. 通信协议：设备之间交流的规则和约定
    1. UART:**Universal Asynchronous Receiver Transmitter** 通用异步收发器
    2. I2C:**Inter-Integrated Circuit** 内部集成电路总线
    3. SPI:**Serial Peripheral Interface** 串行外设接口
    4. CAN:**Controller Area Network** 控制器局域网总线

## 提问

#### 为什么单片机的运行需要时钟基准?

1. 在嵌入式中，任何信号传输都需要多个元件以统一的节奏采样，避免错位
2. 通常MCU中会自带RC振荡电路(由电阻和电容组合实现频率震荡)，产生节奏，精度较差，所以在嵌入式开发中一般需要外接晶振(属于外围电路)，用于获取更精确的时钟信号。从外部晶振获取的时钟信号会在MCU内部被处理成整个系统的主时钟，然后进入时钟树精准分配给各个模块和外设使用

#### 单片机的推挽输出和开漏输出

1. 推挽输出模式的引脚能输出高电平和低电平，高电平对应 **推**，低电平对应 **挽**
2. 开漏输出模式需要外接上拉电阻，高电平为高阻态，低电平接VSS(接地)，外部需要高电平时实际的电流来自上拉电阻，即 **开** 的状态，外部需要低电平时将上拉电源的电流接地，即 **漏** 的状态
